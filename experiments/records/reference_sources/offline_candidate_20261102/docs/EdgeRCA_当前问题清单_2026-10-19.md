# EdgeRCA当前问题清单

更新：2026-10-19。记录本次讨论发现的问题，以Bank第2题（程序行号1）的实际记录为例。单题发现不代表所有题都有相同问题。

**当前已经接通“节点整理→协调者判断→节点补查”的流程，但关键材料可能没有展示出来，展示后也可能被模型误解。原始数据还在，不等于诊断时已经用到了它。**

## 1. 沿着处理流程，问题出在哪里

| 位置 | 已发现的问题与例子 | 应怎样改进 |
|---|---|---|
| 原始数据→候选观测 | Redis02有111种指标，只有25种进入首轮材料，另加2项缺失说明，共27项。其他86种仍可查询，但没有证明它们都无用。 | 保留完整指标目录，区分“尚未展示”与“模型看过后暂留本地”。 |
| 候选观测→4B首轮目录 | 程序从27项中挑12项，依据是类型、名称类别和排列顺序，不是诊断价值。内存“23%→98%→11%”没有入选，4B首轮根本没看到。 | 12应作为每页数量，而不是整个节点只能看12项；让重要变化优先进入，并能继续查看其他概要。 |
| 4B选择“待查” | 各4B可以展开本轮全部概要；本例18节点合计主动将14项标为待查。提示词将“概要看不懂”与“不继续展开”绑在一起；没有要求说明原因，也没有保证稍后自动继续处理。 | 有材料但不理解时先展开；确实缺资料时写清缺什么、怎样补查。待查事项需要后续处理安排。 |
| 4B填写解释 | 旧填写只选“波动、前段较高、证据不足”等，可能忽略中间峰值，也说不清什么支持、什么反驳、什么仍未知。 | 数值继续由程序提供；模型分别说明现象含义、能回答的部分、未知及所需补充。 |
| 中央选择展示材料 | 候选库、模型上报、未查清事项和业务背景混在一起。第一次补查后实际61条正文中，43条是业务/调用关系，原有节点候选只有13条，另5条为补查结果。没有证明这个分配最有利于诊断。 | 分开标明来源、处理状态和是否已读；按当前问题组织支持、反证和缺口，避免大量背景挤占关键变化。 |
| 9B查找未展示材料 | 580项被分成25页目录，每次只显示一页。翻页和节点补查共用最多3次后续调查机会，无法逐页看完。提示词教了翻页，但本题没有使用。 | 提供按组件、指标或事件类型定位的目录；区分读已有材料和重新查询，减少重复补查。不能仅凭没翻页就认定模型不会翻页。 |
| 工具回答时间变化问题 | 9B要求完整内存序列，工具却只给范围、中位数和极值时刻。多个高值采样被压成一个最高值时刻，难以回答何时开始、出现几次、何时下降。 | 按需返回采样点、高值次数、起止观测与采样缺口。对任意提问，明确已回答部分和仍缺内容，不能把同一份统计当成完整回答。 |
| 9B使用补查结果 | Redis02的98%及18:10时刻后来已进入实际输入，9B仍选择Tomcat04内存溢出。它过于相信GC、较高内存和慢调用的组合，没有充分利用反证。 | 让模型核对原因是否有直接支持、是否存在反证；稳定高占用不能直接判故障，GC不能直接判OOM，缺日志不能否定已有指标证据。 |

**补查没有完全解决问题。**先前漏展示的线索可以补回来，但补查机会有限、工具表达不充分、节点解释笼统、中央误判，仍会影响结果。

## 2. 580、12、31、61分别是什么

**12是每个4B节点首轮展示数量的上限，不是每个节点生成材料的数量。**例如Redis02生成27条候选，只给4B首轮看12条；其余候选也登记在中央备用库。因此不能按“12×18”计算中央总量。

本例第一次补查后的数字是：

```text
中央保存580条候选观测
＝18个节点的532条候选
 ＋11条业务运行统计、32条组件调用关联
 ＋9B要求首次补查Tomcat04后，工具生成的5条结果

程序准备展示79条
＝4B选择上报的17条＋4B暂缓展开的14条
 ＋业务/调用关联43条＋补查结果5条

因为输入长度限制，移出18条正文
→ 实际给9B看61条，其余519条仍存档
```

- **业务统计：**请求数量、响应耗时、成功率等；没有可靠组件归属时单独保留。
- **调用关联：**依据父子调用编号连接两个组件，并附调用耗时；连接存在不等于已经确认故障传播方向。
- **待查：**本例是4B主动选择暂不展开，不能当作已经理解或已经确认异常，也不是自动排队后必定处理。
- **目录：**观测的编号、所属节点和主题；看到名称不等于读到了数值。61是程序适配输入长度后的结果，不是模型选出的“最重要61条”。

## 3. 哪些已经改了，哪些仍没验证

- **已接入可选新模式：**4B增加“含义、能回答什么、不能确认什么、下一步查什么”四栏；定向补查结果全部分批填写，不再经过首轮12项筛选。接口已检查，真实模型效果尚未验证。
- **仍待解决：**初始目录只展示12项、待查缺少原因与继续处理安排、中央展示优先规则、25页目录难查、工具缺少完整时间变化信息。
- **已接入独立Top-3候选：**用于检查正确答案是否已进入候选，但必须与首选正确率分开统计；多个竞争解释不能当作同时发生的多个故障。尚无新版真实模型成绩。

当前仍是半小时回放结束后集中分析、服务器顺序模拟多个节点，尚未验证真实边缘设备持续在线协同。不同题目范围、不同时间容差的成绩不能直接比较；当前±5分钟与OpenRCA原评分±1分钟应分别注明。

后续应分别验证两件事：**关键材料是否真正送到了模型面前；模型是否依据这些材料作出了合理判断。**暂不能把全部错误归因于筛选，也不能把保存原文当作问题已经解决。
